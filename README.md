# بات واژگان کلاس

بات .NET 10 با SQLite، برای اجرای محلی و گفت‌وگوی خصوصی تلگرام. برنامه تنها هنگام اجرا و اتصال به Telegram Bot API پاسخ می‌دهد.

## راه‌اندازی

1. با BotFather بات بسازید و توکن را محرمانه نگه دارید. شناسه عددی حساب تلگرام خود را جداگانه به دست آورید؛ نام کاربری کافی نیست.
2. در PowerShell از پوشه پروژه اجرا کنید:

```powershell
$env:BOT_TOKEN = 'توکن بات'
$env:BOT_ADMIN_ID = 'شناسه عددی ادمین'
dotnet run --project VocabularyBot.Bot
```

ادمین و اعضا باید ابتدا `/start` را در گفت‌وگوی خصوصی بات بفرستند. اگر بات پیش‌تر webhook داشته، آن را با Bot API حذف کنید تا long polling فعال شود. برای توقف Ctrl+C را بزنید. توکن را در کد، مخزن یا گفتگو منتشر نکنید.

SQLite و migration در اولین اجرا به طور خودکار ایجاد می‌شوند. مسیر پیش‌فرض ویندوز `%LOCALAPPDATA%\VocabularyBot\vocabulary.db` است. برای تغییر پوشه داده پیش از اجرا `BOT_DATA_DIR` را تنظیم کنید. برای پشتیبان‌گیری، بات را متوقف کنید و فایل پایگاه داده را در محل امن کپی کنید. فقط یک نمونه از بات را هم‌زمان اجرا کنید.

## استفاده

- `/help` فهرست دستورات، `/cancel` لغو فرم فعلی.
- ادمین با `/course`، `/group` و `/week` کلاس، گروه و هفته می‌سازد. فهرست شناسه‌های GUID از `/classes`، `/groups` و `/weeks` قابل مشاهده است؛ شناسه کامل را در فرم‌ها وارد کنید.
- `/users` کاربران ثبت‌نام‌شده را نشان می‌دهد؛ `/member` عضویت، `/leader` تعیین سرگروه و `/admin` اعطای ادمینی را انجام می‌دهند. از شناسه عددی یا نام کاربری فعلی کاربر ثبت‌نام‌شده استفاده کنید.
- اعضا با `/word` در هفته فعال گروه خود واژه ثبت می‌کنند. `/status` گزارش ادمین از تعداد واژه‌های هر عضو است.
- زمان‌ها میلادی و به ساعت تهران هستند. هنگام ساخت هفته، ساعت یادآوری باید در روز پایانی و داخل بازه هفته باشد. زمان پایان مرز انحصاری است.
- یادآوری‌های ارسال‌نشده پس از روشن‌شدن بات مجدداً بررسی می‌شوند؛ ثبت موفق ارسال در SQLite نگهداری می‌شود. در قطعی درست میان ارسال تلگرام و ثبت آن، ارسال تکراری امکان‌پذیر است.

## توسعه

```powershell
dotnet test VocabularyBot.slnx
```

ساختار Domain، Application، Infrastructure و Bot از تفکیک پروژه پرسا الهام گرفته است. موجودیت‌ها به تفکیک حوزه در فایل‌های مستقل قرار دارند؛ کلاس پایه `Entity` با شناسه GUID در Domain و `IGenericRepository` و پیاده‌سازی آن در Infrastructure قرار دارند؛ repository در DI با طول عمر scoped ثبت شده است. برای تغییر ساختار پایگاه داده از EF Core migration استفاده کنید. فایل‌های محلی پایگاه داده و توکن نباید commit شوند.

عملیات تغییر داده و پرس‌وجوها در Application به صورت command و query با handlerهای جداگانه و MediatR پیاده‌سازی شده‌اند. Bot پیام‌ها را از طریق `ProcessMessageCommand` ارسال می‌کند؛ handlerها از generic repository استفاده می‌کنند.

## ارتقا از نسخه قبلی

پیش از اجرای نسخه جدید، بات را متوقف و از فایل SQLite نسخه پشتیبان تهیه کنید. migration خودکار، شناسه‌های عددی داخلی را به GUID تبدیل و روابط را حفظ می‌کند؛ شناسه عددی تلگرام کاربران تغییر نمی‌کند. بازگرداندن migration پشتیبانی نمی‌شود و برای بازگشت باید نسخه پشتیبان بازیابی شود. شناسه‌های عددی قدیمی کلاس، گروه و هفته دیگر در فرم‌ها معتبر نیستند؛ شناسه‌های جدید را از فهرست‌ها دریافت کنید. اگر فرمی قبل از ارتقا نیمه‌تمام مانده، آن را با `/cancel` لغو و دوباره آغاز کنید.
